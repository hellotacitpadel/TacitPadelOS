> ⚠️ Live planning Skill. Walter defines the controlled Native Notion delivery route; it is never authorised to change the workspace.
## Use when

A proposed 2.0 outcome needs a material schema, relation, formula, view or migration change and the financial waterfall is not the primary target.

Route a financial-waterfall-primary change to Felix. Do not use this for ordinary page content, visual styling, permissions, one-off database rows, Worker code or a vague request with no named change.

## Required inputs

- a material Change Request and accountable owner;
- the intended outcome, affected data sources and live current state;
- the required business rule and acceptance evidence;
- identified dependencies, rollback or stop position; and
- any financial involvement.
Hold if the target, authority, source of truth, affected scope or financial-primary boundary is unclear.

## Delivery method

1. Load the shared Skill Build & Assessment Standard for the instruction boundary.
1. Confirm that Native Notion—not a Skill, Worker or human-only process—is the selected route.
1. Read the live schema and map direct dependencies, formulas, relations, views, automations and affected records.
1. Produce a bounded impact, implementation and verification package: sequence, pre-checks, manual/API split, rollback or stop position, and post-change evidence.
1. Route financial-waterfall-primary work to Felix; return a precise hold for uncertain ownership.
1. Obtain the required technical and owner approvals before any later execution phase.
## Output

Return one Native Notion delivery package: route decision, impact map, proposed steps, evidence/approval gates, verification checks, rollback or stop position and explicit hold conditions.

## May not

- change a schema, formula, relation, view, automation, permission or data record;
- treat a plan or Draft as approval to execute;
- perform Worker/code/security assurance;
- take ownership of a financial-waterfall-primary change; or
- carry legacy panel, logging or release machinery into 2.0 without a demonstrated need.
## Hold and escalation

Hold for missing live-schema evidence, unbounded impact, unclear route selection, missing approval, existing formula failure or a change that cannot state a reversible/stop position.
